# Permissions

The plugin uses NetBox ObjectPermissions and standard model permissions.

## Standard actions

User-managed objects use:

```text
view
add
change
delete
```

Bulk operations apply the same ObjectPermission-restricted querysets.

## Cryptographic actions

| Object | Custom actions |
| --- | --- |
| Certificate | `download` |
| Private Key | `download` |
| CSR | `download` |
| Bundle | `export`, `export_pfx` |

Sensitive private-key operations retain the plugin's additional security checks beyond normal ObjectPermissions.

## Management actions

| Object | Custom actions |
| --- | --- |
| Group | `archive_export` |
| Service | `archive_export` |
| Certificate Policy | `archive_export` |
| Object Link | `archive_export` |
| Health Finding | `run_healthscan`, `acknowledge`, `ignore`, `resolve`, `archive_export` |
| Alert Channel | `test`, `archive_export` |
| Alert Rule | `test`, `archive_export` |
| Alert Event | `archive_export` |

Example Django permission codenames:

```text
netbox_certificates.run_healthscan_healthfinding
netbox_certificates.test_alertchannel
netbox_certificates.archive_export_service
```

On NetBox 4.5, custom plugin actions can be entered in ObjectPermission **Additional actions** when a dedicated checkbox is not displayed.

## ObjectLinks

ObjectLink create/change/delete requires ObjectLink permission and visibility of the referenced endpoints. Automatic links are read-only.

## Changes in 1.1.1

Grant `netbox_certificates.archive_export_artifactgroup` (Additional action `archive_export` on Group) to users who should export group archives. View permission alone no longer authorizes that operation. Run migrations to create the permission.

Custom actions apply their own ObjectPermission constraints **and** view constraints. Standard edits and bulk operations retain the corresponding change/delete constraints. Editing a finding to acknowledged, ignored, or resolved additionally requires that named action on the finding, including REST PATCH and bulk operations.

Health findings and delivery events are generated by the engine and have no public `add` permission. The migration removes obsolete add-permission rows. Finding evidence and delivery outcome fields are read-only in REST; operators can update workflow state or descriptive metadata as applicable. Automatic ObjectLinks cannot be edited/deleted individually or in bulk, and their table rows do not offer these actions.

CA-only import uses Certificate `add` permission and checks X.509 CA eligibility. CA resources use Certificate permissions, not the retired internal CertificateAuthority model. Selecting related objects requires visibility; changing Group membership requires change permission on every object added or removed. Services are included in Group membership operations.

Alert settings and settings test endpoints are superuser-only. API writes, health actions, channel/rule tests, and material downloads require a write-enabled NetBox token. SMTP passwords, webhook URLS, and headers remain write-only in REST. Channel/rule test actions additionally require their own `test` permission. SMTP/webhook TLS verification stays enabled by default; an administrator can disable it independently for each transport.
